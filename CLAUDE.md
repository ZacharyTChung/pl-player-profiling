# CLAUDE.md

## Project goal

Reproducible sports-analytics study. Working title:

**"Role Discovery Under Data Scarcity: Unsupervised Player Profiling in the Premier League
After the Withdrawal of Public Advanced Football Statistics"**
Authors: Zachary Chung, Christian Chung.

Discover player archetypes from per-90 statistics using dimensionality reduction and clustering,
instead of accepting listed positions. Validate with cluster stability, a supervised lens and a
cross-season replication. Extend to goalkeepers and team stylistic signatures.

The paper is framed around a constraint that became real during this project: on 20 January 2026
Sports Reference removed every Opta-derived advanced statistic from FBref. The research question is
therefore not only which archetypes exist, but **which archetypes remain recoverable from public
football data after that withdrawal**. Output is a compiled LaTeX paper in which every number comes
from generated macros.

## The data situation (read this before touching features)

Verified directly from our own pull, both seasons:

| FBref table | Columns | All-null | Usable |
|---|---|---|---|
| `passing` | 21 | 19 | 2 |
| `possession` | 21 | 20 | 1 |
| `goal_shot_creation` | 17 | 16 | 1 |
| `defense` | 17 | 14 | 3 |
| `keeper_adv` | 26 | 23 | 3 |
| `passing_types` | 16 | 14 | 2 |
| `standard`, `shooting`, `keeper`, `misc`, `playing_time` | | 0 | all |

FBref still serves the full schema, so the tables look intact until you check for values. Never
select a feature from FBref's published column list without confirming it is non-null in both
seasons. `src/features.py` only contains columns that passed that check.

**Gone:** xG, npxG, xAG, SCA, GCA, all touches, carries, take-ons and progressive counts, all
passing volume, PSxG, sweeper actions, launch rate, pass length, aerial duels, ball recoveries.

**Repair:** Understat is merged in as an independent xG source and restores npxG, xA, key passes,
xGChain and xGBuildup, all fully populated. The combined outfield feature set is 18 features.

**Goalkeepers:** `keeper_core` as originally specified is not recoverable. Only the basic keeper
table survived, so the goalkeeper analysis is limited to shot stopping and workload. The five
composite axes collapse to roughly two. This is reported honestly rather than worked around.

## Ground rules (non-negotiable)

- **No fabricated results.** Every figure, table and numeric claim is generated by code in this repo
  and read from `results/` at build time via `results/macros.tex`. The paper contains no hard-coded
  numbers. If an analysis fails or is degenerate, the paper reports that.
- **Reproducibility is a deliverable.** `make all` regenerates every figure, table and the PDF.
  Everything is seeded from `RANDOM_STATE = 42` in `config.py`. Dependencies pinned via `uv`.
- **Cluster names are hypotheses.** Archetype labels are assigned by inspecting centroid feature
  profiles and member players, never by guessing from a plot. Justifications live in
  `results/archetypes.json` and are quoted verbatim by the paper.
- **Respect FBref.** All access goes through `soccerdata`, which caches to disk and rate-limits at
  7 s/request. Never write a raw-request loop against fbref.com. Raw HTML is cached before any
  transformation so the scrape never runs twice.
- **Paper writing style.** Plain, direct academic prose. No em dashes or en dashes anywhere in the
  paper; use commas, colons or separate sentences. No sentences starting with "And". No bullet
  points in the paper body. Sentences may run long. Banned filler: "delve", "leverage",
  "it is worth noting", "in the realm of". Enforced by a pre-commit hook.

## Environment

- Python **3.12.14**, managed by `uv`. The system Python (3.14) cannot run this project.
- `brew install libomp` is required for LightGBM on Apple Silicon.
- A TeX distribution is required for the paper build. This repository was built against
  **TinyTeX**, installed per user with no administrator rights:
  `curl -sL https://yihui.org/tinytex/install-bin-unix.sh | sh`, followed by
  `tlmgr install booktabs siunitx natbib caption subcaption hyperref geometry cm-super multirow`.
  The Makefile adds `~/Library/TinyTeX/bin/universal-darwin` to PATH automatically. A
  system wide MacTeX install works equally well and takes precedence when present.

## Critical decision: the soccerdata version problem

FBref sits behind Cloudflare and returns 403 to ordinary HTTP clients.

- **soccerdata 1.8.8** exposes all 11 season stat tables but its FBref reader subclasses
  `BaseRequestsReader` (TLS-requests only). It is blocked by Cloudflare: verified, 403 on every retry.
- **soccerdata 1.9.1** migrated FBref to the seleniumbase driver and clears Cloudflare, but the same
  rewrite reduced the season stat tables to five: standard, keeper, shooting, playing_time, misc.
  The six dropped tables (passing, passing_types, goal_shot_creation, defense, possession,
  keeper_adv) supply most of `outfield_core` and all of `keeper_core`.

**Resolution:** pin `soccerdata==1.9.1` for its working driver and restore the dropped tables with
the `FBrefFull` subclass in `src/ingest.py`. The subclass re-declares only the allowed stat_type
list, the URL slug map and the table-id map, and reuses soccerdata's own downloader, cache and table
parser. Two things had to be discovered empirically against live FBref pages:

- `goal_shot_creation` lives at `/gca/` and its table id is `stats_gca`, not
  `stats_goal_shot_creation`. soccerdata 1.8.8 looked for the latter, so its GCA path was broken.
- `BaseReader._all_leagues()` filters the league dictionary by `cls.__name__`, so any subclass
  resolves to zero valid leagues unless it overrides that classmethod.

## Multi-league replication

`src/leagues.py` repeats the pipeline on the other four big-five leagues for the primary
season. The declared rule returns k=2 in all five, and every defensive elasticity in every
league falls below one. Raw tables cache under `data/raw/leagues/`. Outside `make all`
because it scrapes.

## Analyses deliberately skipped or forced out by the data

- **Goalkeeper composites** (Phase 8 as specified): sweeping, distribution, cross handling and
  aerial claims all depended on `keeper_adv`, which is empty. Reduced to shot stopping and workload.
- **Possession and passing features** across every phase: unavailable, see the data situation above.

- **Role drift within a season** (Phase 10 option 3): originally dropped as rate-limit
  hostile, now completed for one club. Match reports turned out to survive the withdrawal
  better than the season tables: the withdrawn columns are absent from the match schema
  rather than present and empty, and all but two of the remaining columns are populated.
  See `src/drift.py`.
- **Age and archetype** (Phase 10 option 5): originally not selected, now completed. Only defenders show an association, and the crossing archetype is 1.65 years younger.

Both are recorded in the paper as future work.
